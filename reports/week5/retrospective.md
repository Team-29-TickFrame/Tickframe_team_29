# Sprint Retrospective

## What Went Well

- Architecture documentation was added for static, dynamic, and deployment views.
- ADRs were recorded and linked to quality requirements.
- Development process and configuration-management documentation were updated.
- Existing CI, testing, and quality documentation stayed linked from the Week 5 report.

## What Did Not Go Well

- Architecture documentation took longer than expected.
- Some documentation work moved close to the deadline.
- The planned customer meeting did not take place, so Week 5 customer UAT and Sprint Review evidence is missing.
- Final release and product-access evidence still needs to be confirmed publicly.

## Changes Compared With The Previous Sprint

- Documentation links were organized through the Week 5 report.
- Architecture documentation, ADRs, quality requirements, and testing artifacts were connected.
- Customer feedback from previous reviews was mapped to Sprint 3 issues.

## Process Improvements For The Next Sprint

- Update architecture docs in the same PR as architecture-affecting code changes.
- Record ADRs when decisions are made, not at the end of the Sprint.
- Reserve time for a documentation review before the customer session.
- Assign a backup presenter for Sprint Review and UAT.
- Keep release, deployment, and CI evidence links in the report as they are produced.
